## Finding: quoted secrets survive migration error logging

**P1 — `src/db/config.ts`, `CREDENTIAL_PAIR` / `redactSecrets`.**
The new migration logger prints arbitrary driver error messages after regex
redaction. The credential regex excludes quotes at the start of a value and
does not support quoted JSON keys. These common representations therefore pass
through verbatim into build logs:

```text
password='synthetic-secret'
{"password":"synthetic-secret"}
```

Both were reproduced with
`describeMigrationError(new Error(message)).includes("synthetic-secret") === true`.
An unquoted `password=synthetic-secret` is redacted correctly. No real credentials
were used or accessed in this reproduction.

Claude should handle quoted values, JSON keys and escaped quotes (and any
relevant credential aliases), or restrict output to known-safe error fields.
Add regressions proving the complete value is absent while useful SQL details
remain. This is a backend-owned fix; Codex has not changed those files.
